# VNE RAMOK 23 — Launching a public portfolio demo

Это портфолио, а **не магазин с оплатой**. Платежей нет и не будет в этом демо.

## 1. Проверь локально

Требуется Node.js 22.13+.

```sh
npm test
npm start
```

Windows: `start_windows.bat`. Адрес `http://localhost:3000`.

Полная локальная версия сохраняет аккаунты и заявки в SQLite. Для проверки публичного деморежима:

**PowerShell**
```powershell
$env:PUBLIC_DEMO="1"
node server.js
```

**CMD**
```bat
set PUBLIC_DEMO=1
node server.js
```

В публичном режиме клиентские данные не записываются; админка и авторизация отключены, а остатки не изменяются. Формы заранее заполнены вымышленными данными. Чек помечен как demo.

## 2. Подготовь GitHub

1. Создай новый пустой репозиторий `vne-ramok` на GitHub.
2. Извлеки содержимое `VNE_RAMOK_23_FULL.zip` и найди папку `vne-ramok`.
3. В терминале этой папки:

```sh
git init
git add .
git commit -m "VNE RAMOK 23: unified 3D portfolio studio"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/vne-ramok.git
git push -u origin main
```

Замени YOUR_USERNAME своим логином. При желании используй GitHub Desktop вместо команд.

**Перед push:** проверь `git status`, убедись, что `data/`, `uploads/`, `.env`, SQLite и личные данные отсутствуют в коммите. Они уже перечислены в `.gitignore`.

## 3. Опубликуй на Render

1. Зайди на https://dashboard.render.com/ и подключи GitHub.
2. Нажми **New → Blueprint** и выбери репозиторий проекта.
3. Render прочитает `render.yaml` и соберёт приложение через Dockerfile.
4. После деплоя появится адрес вида `https://<service>.onrender.com`.
5. Проверь `/api/health`: `mode` должен быть `public-demo`; админка должна возвращать 404.
6. Пройди сценарии каталога, OUTFIT STUDIO, корзины и анимированного чека.

`render.yaml` использует план `free`, если он доступен в вашем аккаунте. Может потребоваться выбрать другой план. На хостингах с **ephemeral filesystem** SQLite при переразвертывании пересоздаётся; для портфолио это допустимо, потому что публичные заказы и аккаунты не сохраняются.

## 4. Что показать в портфолио

- Живую ссылку на демо и GitHub-код;
- взаимодействие с 3D-конструктором (вращение, выбор вещей, цветов);
- LOOKBOOK, каталог, корзину и анимированный чек;
- README, тесты и краткую архитектуру бэкенда;
- пометку **Demo only — no payments or saved customer data**.

## Известные ограничения

- Стилизованные 3D-модели не обеспечивают точную примерку или физику ткани.
- Нельзя гарантировать WebGL на любом устройстве; при ошибке доступен резервный эскиз.
- На публичном сервере нет регистрации и административной обработки заявок. Полная логика есть в локальном режиме.
- Деплой требует вашего аккаунта Render и опубликованного GitHub-репозитория; ZIP сам по себе не создаёт URL.
